# Project UI audit — October 16, 2026

41 consolidated findings: 9 high, 24 medium and 8 low priority. Confidence is listed for each finding; conditional/network-dependent and source-review candidates are not presented as universally reproduced defects.

## Coverage and limits

- 205 distinct GET URLs inspected; 205 desktop render checks at 1440px and 129 phone render checks at 390px. The inventory includes a small number of direct resource/AJAX routes, whose failures are distinguished from visible navigation defects.
- 20 additional protected layouts previewed in a local, non-persisted permission context. This reviews markup/layout and is not proof the current account can access or operate those screens. No account permissions were changed.
- 449 Blade templates statically scanned for asset references and legacy interaction attributes; shared layouts and implicated views manually reviewed. This is not a claim that every dormant template was manually exercised.
- Final GET results: 129 HTTP 200, 56 HTTP 403, 3 HTTP 404, 1 HTTP 422, 16 HTTP 500. HTTP 403 results are account-access restrictions, not automatically UI bugs.
- No forms were submitted to existing records, no notifications or emails were sent, and no UI fixes were applied. Existing application edits were preserved.
- CDN failures are explicitly conditional: external assets were unavailable in the audit environment. Portal authenticated screens, live mailbox/Google/webmail flows, successful saves, destructive actions, every modal state, all browsers and every viewport size are outside this read-only audit.
- The GET tour-view side effect is documented in UI-41. Two exact, unchanged empty rows attributable to the audit were archived and removed. A concurrent browser edit to client 10 was left intact. No other database-table difference remained in the preservation check.
